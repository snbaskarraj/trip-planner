# API Contract — Trip Planner

The seam between `specs/frontend-spec.md` and `specs/backend-spec.md`. Field names and status codes here are the source of truth for both implementations.

Base URL (local): `http://localhost:8000`

Error body (unless a more specific shape is listed):

```json
{ "detail": "human-readable message", "code": "OPTIONAL_STABLE_CODE" }
```

Validation errors from the request schema use `422` with FastAPI’s standard `{ "detail": [ ... ] }` body.

## Trips

### `GET /api/trips`

| Status | Body |
|---|---|
| 200 | `{ "trips": [ TripSummary, ... ] }` |

`TripSummary`:

```json
{
  "id": 1,
  "title": "Kyoto in April",
  "destination": "Kyoto",
  "start_date": "2026-04-10",
  "end_date": "2026-04-14",
  "created_at": "2026-09-20T04:30:00Z"
}
```

### `POST /api/trips`

Request:

```json
{
  "title": "Kyoto in April",
  "destination": "Kyoto",
  "start_date": "2026-04-10",
  "end_date": "2026-04-14"
}
```

| Status | When | Body |
|---|---|---|
| 201 | created | `TripDetail` |
| 400 | `end_date` before `start_date` | `{ "detail": "...", "code": "END_BEFORE_START" }` |
| 422 | missing/invalid fields | FastAPI validation body |

### `GET /api/trips/{trip_id}`

| Status | Body |
|---|---|
| 200 | `TripDetail` |
| 404 | `{ "detail": "Trip not found" }` |

### `PATCH /api/trips/{trip_id}`

Request: any subset of `{ title, destination, start_date, end_date }`.

| Status | Body |
|---|---|
| 200 | `TripDetail` |
| 400 | inverted dates | `{ "detail": "...", "code": "END_BEFORE_START" }` |
| 404 | `{ "detail": "Trip not found" }` |

### `DELETE /api/trips/{trip_id}`

| Status | Body |
|---|---|
| 204 | empty |
| 404 | `{ "detail": "Trip not found" }` |

`TripDetail`:

```json
{
  "id": 1,
  "title": "Kyoto in April",
  "destination": "Kyoto",
  "start_date": "2026-04-10",
  "end_date": "2026-04-14",
  "share_token": "a1b2c3d4e5f6",
  "created_at": "2026-09-20T04:30:00Z",
  "updated_at": "2026-09-20T04:30:00Z",
  "days": [ DayDetail, ... ]
}
```

`share_token` is generated by the server. Clients must not send it on create.

## Days

### `POST /api/trips/{trip_id}/days`

Request:

```json
{
  "date": "2026-04-11",
  "start_time": "09:00",
  "end_time": "18:00",
  "notes": "Temples in the east",
  "position": 0
}
```

`start_time` / `end_time` are optional `HH:MM` 24-hour strings. `notes` and `position` are optional.

| Status | When | Body |
|---|---|---|
| 201 | created | `DayDetail` |
| 400 | end time before start time | `{ "detail": "end_time must not be before start_time", "code": "END_BEFORE_START" }` |
| 404 | trip missing | `{ "detail": "Trip not found" }` |
| 422 | bad types | FastAPI validation body |

### `PATCH /api/days/{day_id}`

Request: any subset of `{ date, start_time, end_time, notes, position }`. Send `null` to clear a time.

| Status | Body |
|---|---|
| 200 | `DayDetail` |
| 400 | inverted times | `{ "detail": "end_time must not be before start_time", "code": "END_BEFORE_START" }` |
| 404 | `{ "detail": "Day not found" }` |

### `DELETE /api/days/{day_id}`

| Status | Body |
|---|---|
| 204 | empty |
| 404 | `{ "detail": "Day not found" }` |

`DayDetail`:

```json
{
  "id": 10,
  "trip_id": 1,
  "date": "2026-04-11",
  "start_time": "09:00",
  "end_time": "18:00",
  "notes": "Temples in the east",
  "position": 0,
  "activities": [ ActivityDetail, ... ]
}
```

## Share (read-only, no login)

### `GET /api/share/{token}`

| Status | Body |
|---|---|
| 200 | `TripDetail` (same shape as `GET /api/trips/{id}`) |
| 404 | `{ "detail": "Shared trip not found" }` |

There are no `POST` / `PATCH` / `DELETE` routes under `/api/share`. Writes require the numeric trip/day/activity ids from the editor API.

## Day conditions (maps / weather)

### `GET /api/days/{day_id}/conditions`

Called only by the Itinerary Editor and Share View weather panels. Implemented by the server-side wrapper; the API key never appears in this response.

**Success**

```json
{
  "status": "ok",
  "destination": "Kyoto",
  "date": "2026-04-11",
  "temperature_c": 18.4,
  "summary": "Partly cloudy",
  "wind_kph": 9.2
}
```

**Upstream failure or timeout (expected — not an exception)**

```json
{ "status": "unavailable" }
```

| Status | When | Body |
|---|---|---|
| 200 | wrapper succeeded | success shape above (`status: "ok"`) |
| 200 | vendor timeout, HTTP error, missing/invalid key, parse error, network error | `{ "status": "unavailable" }` |
| 404 | day does not exist | `{ "detail": "Day not found" }` |

This endpoint **never** returns 5xx because the maps/weather vendor failed. An upstream outage is a 200 + `unavailable` so the frontend can keep rendering the itinerary.
